# i18n — MWANAKIN SOUND multilingue (Lingala + monde entier)

Objectif : une plateforme **entièrement traduisible**, Lingala en vedette, puis
les grandes langues-relais **continent par continent**. Les dictionnaires sont du
**JSON pur** (`lib/i18n/messages/*.json`) : portables tels quels dans le Next.js
**et** dans le front kinshasa-beats (Vite/TanStack).

## Ce qui est livré

- `lib/i18n/locales.ts` — registre des langues (endonyme, sens d'écriture, statut)
  - carte `CONTINENT_LOCALES` (quelle langue proposer selon le continent).
- `lib/i18n/index.ts` — chargeur sans dépendance : `translate(locale, key, vars)`,
  `createTranslator(locale)`, `getDictionary(locale)`. Repli en cascade
  **langue → français (référence) → clé brute**, interpolation `{var}`.
- `lib/i18n/messages/{fr,en,ln,sw,pt,es,ar}.json` — 7 langues.
- `tests/i18n.test.ts` — garantit que **toutes les langues ont exactement les
  mêmes clés** (aucune traduction manquante) et que la marque reste « MWANAKIN SOUND ».

## Langues et couverture continentale

| Code | Langue      | Statut    | Porte surtout                          |
| ---- | ----------- | --------- | -------------------------------------- |
| `fr` | Français    | natif     | Afrique francophone, Europe, Amériques |
| `en` | Anglais     | natif     | Monde entier (relais)                  |
| `ln` | **Lingala** | brouillon | RDC / Congo — **langue-vedette**       |
| `sw` | Swahili     | brouillon | Afrique de l'Est & centrale            |
| `pt` | Portugais   | brouillon | Angola, Mozambique, Brésil, Portugal   |
| `es` | Espagnol    | brouillon | Amériques, Europe                      |
| `ar` | Arabe (RTL) | brouillon | Afrique du Nord, Moyen-Orient          |

`status: draft` = traduction de première main à **faire valider par un locuteur
natif** (surtout les titres de sections). `fr` et `en` sont fiables.

### Note sur le Lingala et « le dictionnaire de la Bible »

Le Lingala fourni suit le **registre standard/littéraire** — celui de la _Biblia_
en lingala, le corpus écrit le plus stable et le plus largement compris (rumba,
gospel, prédication). C'est exactement ce socle « biblique » demandé : un lingala
soigné, compréhensible de Kinshasa à Brazzaville. Quelques choix :

- `gospel` → **« Nzembo ya Nzambe »** (chant de Dieu).
- `wallet` → **« Libenga »** (bourse/poche) — jamais « mbongo » (argent), car les
  MwanaCoins **ne sont pas** une monnaie ; `wallet.not_money` le rappelle.
- `nature`/ambiance → **« Kimia »** (paix/calme).

Pour enrichir : ajouter des clés dans `fr.json` (référence), puis dans chaque
langue — le test de parité échoue tant qu'une clé manque quelque part.

## Brancher dans le front (dès que Lovable est rechargé)

1. Copier `lib/i18n/` dans le repo kinshasa-beats (ou le publier en package partagé).
2. Détecter la langue : `profiles.preferred_language` (déjà en base) → sinon
   `Accept-Language` → sinon `CONTINENT_LOCALES` via la géo → défaut `fr`.
3. Remplacer les libellés en dur par `t('nav.home')`, etc. Poser `dir="rtl"` sur
   `<html>` quand `LOCALES[locale].dir === 'rtl'` (arabe).
4. Un sélecteur de langue dans `Réglages`, écrivant `profiles.preferred_language`.

## Ajouter une langue

1. Créer `lib/i18n/messages/<code>.json` (copier `fr.json`, traduire).
2. Déclarer la langue dans `LOCALES` + l'ajouter au(x) continent(s) pertinent(s).
3. L'importer dans `index.ts`. `npm test` valide la parité des clés.
